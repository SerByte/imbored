# Английская версия сайта (i18n)

Документ — общий договор для всех, кто переводит сайт. Если код расходится с
ним, правится одно из двух в том же коммите, а не «потом».

## Адреса

- Русский остаётся без префикса: `/play`, `/game/730`. Ни одна старая ссылка,
  карта сайта и закладка не меняются.
- Английский — под `/en`: `/en/play`, `/en/game/730`, `/en` — главная.
- `/ru/*` снаружи не живёт: постоянный редирект на адрес без префикса.
  Исключение — файловые карточки (`…/opengraph-image`): их адрес Next
  собирает из пути маршрута, у русской страницы og:image — `/ru/…`, и они
  отдаются как есть, без круга редиректа (`lib/i18nroutes.ts`).
- Внутри приложения всё, что рендерит страницы, лежит в `app/[lang]/…`.
  Русские адреса доезжают туда правилами `rewrites` из `next.config.ts`
  (`/play` → `/ru/play`) — без прокси и без функции, CDN понимает их сам.
  Список разделов для переписывания — `LOCALIZED_SECTIONS` в `lib/i18n.ts`;
  что каждый каталог `app/[lang]/*` в нём есть, сторожит тест
  (`lib/i18nroutes.test.ts`). Переписываются формы настоящих маршрутов
  раздела (`SECTION_SHAPES` в `lib/i18nroutes.ts`: `/game/<appid>/news`,
  `/games/<жанр из списка>`), а не всё под ним; что каждая страница,
  обработчик и карточка под `app/[lang]` там есть, сторожит тот же тест.
- Неизвестный адрес под `/en` (`/en/xyz`, `/en/quiz/xyz`) ловит
  `app/[lang]/[...missing]` — 404 на своём языке, с шапкой. Она динамическая:
  каждый такой адрес — рендер функцией. Шапку и экран такой 404 рисует
  клиент: `notFound()` из страницы в этой версии Next отдаёт вместо HTML
  пустую оболочку `<html id="__next_error__">` (граница not-found —
  клиентский error boundary, серверный рендер React его не исполняет). Так
  же было и до перевода у `/game/<нет такой>`.
- Адрес вне всех разделов (`/xyz`, `/wp-admin/x`, `/.env`) и опечатку под
  русским разделом (`/quiz/xyz`, `/games/<нет такого жанра>`,
  `/game/730/xyz` — её формы маршрутов не переписывают) правило
  `afterFiles` уводит в одну статическую 404 — `/_not-found`, который Next
  собирает из `app/global-not-found.tsx`: там корневой layout с языком `ru`
  и тот же экран 404 с полкой (`NotFoundView` из `app/[lang]/not-found.tsx`).
  Это единственная 404, которую сервер рисует целиком — со шапкой, подвалом
  и полкой, как до `[lang]`, — и отдаёт её CDN, без функции, сколько бы
  адресов ни перебрал сканер. Страницей с `notFound()` (была
  `app/[lang]/missing`) её не сделать: HTML был бы пустой оболочкой.
  Именно `afterFiles`: файлы `public/` и корня `app/` к этому шагу уже
  отданы, а правило в `beforeFiles` отнимало у них адрес. Под `/api` такой
  адрес получает JSON-404 (`app/api/[...missing]`). Тот же `/_not-found`
  отвечает адресам под `/_next` и `/_vercel`, которых нет (`/_next/xyz`), —
  по-русски. Собственные пути Next — `/_next/static`, `/_next/image`,
  `/_next/data` — правило не трогает: их отдаёт сам Next, а промах
  `/_next/static` CDN отвечает коротким текстовым 404.
  Заголовок кэша у этой 404 под `next start` — ISR полки (`s-maxage=86400,
  stale-while-revalidate=…`), а не `private, no-store`, как до `[lang]`:
  HTML один на всех, новый адрес приходит только деплоем, а деплой кэш CDN
  сбрасывает (почему no-store не вернуть — `garbageRewrites` в
  `lib/i18nroutes.ts`).
  Код и noindex. Под `next start` ответ — 404, и noindex в нём ставит сам
  Next. На Vercel тот же пререндер CDN отдаёт как обычную статическую
  страницу: замер прода 19.10.2026 — `/games/nonexistent-genre`, `/quiz/xyz`,
  `/xyz`, `/.env` отвечали `200` с `Cache-Control: public, max-age=0,
  must-revalidate` и без единого `<meta name="robots">`, мягким 404 с
  заголовком главной. Поэтому noindex — в метаданных самой 404
  (`app/global-not-found.tsx`): он лежит в HTML при любом коде. Настоящий код
  404 на Vercel этим не возвращается — это отдельная правка маршрутизации, и
  до неё прод так и отвечает `200`. Проверка после деплоя — `npm run smoke` с
  `SMOKE_BASE_URL=https://imbored.cc` (шаг «мусорный адрес… — 404 с
  noindex»): noindex там строгий, а код против не-localhost — только
  предупреждением. Строго код проверяет `SMOKE_EXPECT_404=1` — этим прогоном
  и проверят правку маршрутизации. CI на `next start` видит 404 всегда, и там
  код строгий.
- Регистр. Правила `rewrites` и `redirects` Next сравнивает с адресом без
  учёта регистра, и отличить `/EN` от `/en` правилом нельзя. Поэтому
  `afterFiles` переписывают «en» в любом регистре в `/en`
  (`lib/i18nroutes.ts`): `/EN/play` — английская страница с canonical
  `/en/play` и той же записью ISR, а не пустая оболочка 404 с русской
  головой и своей записью на каждый вариант регистра (на диске Windows —
  поверх записи `/en`). `/RU/…` уводит тот же редирект, что `/ru/…`. Раздел
  в чужом регистре (`/Play`, `/en/Play`) правило от своего не отличит: его
  ловит `app/[lang]/[...missing]`.
- `dynamicParams = false` в корневом layout НЕ ставится: в этой версии Next
  флаг решается по всей цепочке сегментов, и в корне он сделал бы 404 из
  каждой `/game/<appid>` вне `generateStaticParams`. Чужой язык ловит сам
  layout (`notFound()`), а страницы без других параметров ставят флаг у себя.
- `revalidatePath` — только через `revalidateSitePath` (`lib/revalidate.ts`):
  ISR кэширует страницу по пути маршрута (`/ru/game/730`, `/en/game/730`), и
  голый `/game/730` не сбросил бы ни одной копии.
- В корне `app/` остаются: `api/`, `globals.css`, `global-error.tsx`,
  `global-not-found.tsx`, `sitemap.ts`, `robots.ts`, `manifest.ts`, иконки и
  служебные роуты без языка (`indexnow-key.txt`, `search-index.json` — в
  индексе поиска только номер и название игры). RSS-ленты `/whatsnew` и
  PNG-карточки портрета — под `[lang]`: в них текст для человека.
- Манифест PWA — по одному на язык (`manifestFor(locale)` в
  `lib/manifest.ts`): русский — `/manifest.webmanifest` (`app/manifest.ts`),
  английский — `/manifest.en.webmanifest` (route handler в корне, свои `id` и
  `start_url` `/en`, ярлыки в `/en/…`, снимки `public/screenshots/*.en.jpg`).
  Корневой layout на `en` ссылается на английский (`metadata.manifest`), на
  русском его ставит файл. Не `/en/manifest.webmanifest`: под `/en` живут
  только разделы, а русскому `/manifest.webmanifest` пришлось бы стать
  разделом, и `beforeFiles` отнимало бы его у файла.
- Главная `/` обязана оставаться статической (bundle-budget.json, `static`):
  для обоих языков её отдаёт CDN.

## Как страница узнаёт язык

| Где | Чем | Откуда |
|---|---|---|
| Серверный компонент, generateMetadata | `await getLocale()` | `lib/i18n-server.ts` (поверх `next/root-params`) |
| Страница или layout с тестами, generateMetadata | `toLocale((await params).lang)` | `params` маршрута: `next/root-params` вне сборки (vitest) бросает при импорте |
| opengraph-image, route handler под `app/[lang]` | `toLocale((await params).lang)` | `params` маршрута: это route handlers, `next/root-params` там не работает |
| Клиентский компонент | `useLocale()` | `components/LocaleProvider.tsx` (контекст, ставит корневой layout) |
| Route handler (`app/api/*`) | `localeFromRequest(req)` | `lib/i18n.ts`: `?lang=en` в адресе |
| Чистая функция в `lib/` | параметр `locale: Locale = 'ru'` | вызывающий передаёт |

`next/root-params` не работает в клиентских компонентах, Server Actions и
route handlers — поэтому там свои способы. Без провайдера `useLocale()`
возвращает `'ru'`: старые тесты, рендерящие компонент голым, не ломаются.

Route handler и файловая карточка под `app/[lang]` рендерятся мимо корневого
layout, и его `notFound()` на чужой язык их не закрывает. Поэтому такой
обработчик начинается с `if (!isLocale(lang)) return …404` — или стоит под
`dynamicParams = false`, и язык решает сборка (сторожит
`lib/i18nroutes.test.ts`).

Клиент, который ходит в API за текстом для человека (причины подбора, ошибки,
подписи), добавляет язык в адрес: `withLang('/api/recommend?x=1', locale)`.
Язык в адресе, а не в куке или заголовке: ответы GET могут кэшироваться, и
ключом кэша обязан быть сам адрес.

## API модуля `lib/i18n.ts` (чистый, годится клиенту)

```ts
export const LOCALES = ['ru', 'en'] as const
export type Locale = (typeof LOCALES)[number]
export const DEFAULT_LOCALE: Locale = 'ru'
export const LANG_COOKIE = 'lang'            // явный выбор человека в переключателе
export function isLocale(v: unknown): v is Locale
export function toLocale(v: unknown): Locale  // неизвестное → 'ru'

// Строка по языку. Обе ветки обязательны — тип не даст забыть английскую.
export function tr<T>(locale: Locale, v: { ru: T; en: T }): T

// Число с формой слова. ru: [одна, две, пять], en: [one, other].
// Возвращает ТОЛЬКО слово; число вызывающий ставит сам, как и раньше с plural().
export function pl(locale: Locale, n: number, forms: { ru: [string, string, string]; en: [string, string] }): string

export function intlLocale(locale: Locale): 'ru-RU' | 'en-US'
export function fmtNumber(locale: Locale, n: number, opts?: Intl.NumberFormatOptions): string
export function fmtDate(locale: Locale, d: Date | number, opts: Intl.DateTimeFormatOptions): string // number — секунды unix

// Ссылки
export function lp(locale: Locale, href: string): string   // '/play' → '/en/play' для en; внешние, '#…', '/api/…', файлы — без изменений
export function splitLocale(pathname: string): { locale: Locale; path: string } // '/en/play' → { en, '/play' }
export function switchLocaleHref(pathname: string, target: Locale, search?: string | URLSearchParams): string // search — строка запроса, едет с адресом
export function withLang(url: string, locale: Locale): string // добавляет lang=en в query; для ru — без изменений
export function localeFromRequest(req: Request | { url: string }): Locale
export function htmlLang(locale: Locale): string  // 'ru' | 'en'
export function ogLocale(locale: Locale): 'ru_RU' | 'en_US'
export function alternates(path: string, locale?: Locale): { canonical: string; languages: Record<string, string> } // canonical — на языке locale (по умолчанию ru), x-default — английская версия; в generateMetadata — localeAlternates из lib/site.ts

// Служебное
export const LOCALIZED_SECTIONS: readonly string[]  // первые сегменты под app/[lang]: rewrites и префикс lp()
export function routePaths(path: string): string[]   // '/game/730' → ['/ru/game/730', '/en/game/730'] — для revalidatePath
export function preferredLocale(o: { acceptLanguage?: string | null; cookie?: string | null }): Locale | null // кука, иначе какой из двух браузер ставит выше; null — ни одного; ступень homeLocaleFor (lib/homelocale.ts)
```

`fmtDate` без своей `timeZone` печатает UTC — как остальные даты сайта
(сервер и браузер обязаны напечатать один день).

`lib/site.ts`: `siteTitle(locale)`, `siteDescription(locale)`, `ogSite(locale)`,
`localeAlternates(locale, path)`; `ownAddress(path)` и `rootCard(props, parent)` сами берут язык из `params`.
Русские `SITE_TITLE`, `SITE_DESCRIPTION`, `OG_SITE` остаются ради старых
вызывающих и тестов; манифест берёт `siteTitle` и `siteDescription` своего
языка (`manifestFor` в `lib/manifest.ts`).
JSON-LD (`lib/jsonld.ts`) берёт `locale` страницы: адреса в разметке — на её
языке, как canonical (`/en/game/730`, а не `/game/730`), а `WebSite` главной —
с языком и описанием своей версии. `lib/tagsru.ts`: `tagLabel(tag, locale)`.

Плюс в `components/`:

- `LocaleProvider`, `useLocale()` — контекст языка.
- `Link` (`@/components/Link`) — замена `next/link` с теми же пропсами,
  которая сама ставит префикс языка у внутренних адресов. Импорт
  `next/link` в коде страниц после перевода не остаётся (сторожит
  `lib/i18nlink.test.ts`); исключение — сам `components/Link.tsx`.
  `useLinkStatus` — тоже оттуда.
- `useLocaleRouter` (`@/components/useLocaleRouter`) — `useRouter` из
  `next/navigation`, у которого `push`, `replace` и `prefetch` сами ставят
  префикс языка. `useRouter` из `next/navigation` в коде страниц не
  импортируется (сторожит тот же `lib/i18nlink.test.ts`).
- Вход через Steam знает язык: `/api/auth/steam` берёт его из `?lang=` или из
  Referer своей страницы и везёт через Steam в `return_to`, возврат ведёт на
  страницу того же языка (и отказ — на лендинг того же языка).
- `StaticGameCardBody` (`components/StaticGameCard`) — серверная капсула хабов и 404 — берёт язык обязательным
  пропом `locale`: по нему название получает `lang` (`langOn`), как у клиентской `GameCardName` (та читает
  `useLocale()`). Серверной карточке контекст клиента не виден.
- `LocaleSwitch` — переключатель «RU / EN» в подвале: ведёт на тот же адрес
  (с запросом) в другом языке и пишет куку `lang`. В мобильной панели его
  нет: пять колонок на 360 px заняты целиком, а меню или шторки, где он
  встал бы сам собой, у панели нет; подвал на телефоне докручивается.
- Главная. Английский — язык по умолчанию для нового гостя, русский — для
  гостя из СНГ; адреса прежние (русский без префикса, английский под `/en`).
  «/» выбирает язык по порядку:
  1. кука `lang` — явный выбор: `lang=en` уводит на `/en` правило
     `redirects` из `next.config.ts` (`homeLocaleRedirects`), с любой
     сессией; `lang=ru` — остаться;
  2. краулер или бот превью ссылок (по User-Agent; и без Accept-Language —
     браузер шлёт его всегда) — русская главная, без редиректа;
  3. страна из `CIS_COUNTRIES` (`x-vercel-ip-country`: члены СНГ и
     Туркменистан; Украины и Грузии нет — они не в СНГ) — русская, какой бы
     ни был браузер;
  4. браузер ставит русский выше английского (`preferredLocale`) — русская:
     «uk-UA,uk;q=0.9,ru;q=0.8,en;q=0.7» и вне СНГ;
  5. остальные — 307 на `/en` (английский, немецкий, китайский браузер),
     строка запроса едет с ним.

  Шаги 2–5 — `homeLocaleFor` в `lib/homelocale.ts`, его зовёт `proxy.ts`.
  В прокси, а не правилом конфига, ради страны: `x-vercel-ip-country`
  документирован для функций и middleware. Прокси стоит на «/» не голым
  адресом, а записью matcher с has/missing: CDN сам проверяет, что это
  документ (`Sec-Fetch-Dest: document`), без куки `lang` и без сессии, не
  запрос роутера (`RSC`, `Next-Router-Prefetch`) и не переход со своей
  страницы (`Sec-Fetch-Site: same-origin`), — и только тогда будит функцию.
  Остальные просмотры главной и префетч логотипа идут мимо неё, главная
  остаётся статикой с CDN. Имена кук в matcher записаны строками (Next
  читает его статическим разбором) — что они равны `LANG_COOKIE` и
  `SESSION_COOKIE`, стережёт `lib/homelocale.test.ts`.

  Только вход на сайт — запросы роутера и переходы со своих страниц не
  уводятся. С сессией без куки `lang` (вошедшие до английской версии) —
  русская главная. Вход с английской версии (Steam или карточка на
  лендинге) пишет `lang=en` сам — иначе вошедшего с сессией «/» вёл бы на
  русскую. Без заголовка страны (локальный `next start`) решает браузер.
  Решение прокси не запоминает: куку `lang` пишет только выбор человека,
  поэтому без выбора страна и браузер читаются на каждом входе — так и
  сказано в политике («при каждом входе», а не «один раз»).

## Как переводить строку

1. Строка интерфейса — рядом с местом вывода, парой:
   `tr(locale, { ru: 'Подобрать игру', en: 'Find a game' })`.
   Не в центральный JSON: так перевод виден рядом с русским, и параллельные
   правки разных файлов не сталкиваются в одном словаре.
2. Длинный блок страницы (privacy, лендинг) можно вынести в объект
   `const COPY = { ru: {...}, en: {...} } satisfies Record<Locale, …>` в том же
   файле или рядом (`page.copy.ts`).
3. Окончания по числу — `pl()`, а не `plural()`. Числа — `fmtNumber()`, даты —
   `fmtDate()`. `toLocaleString('ru-RU')` в выводе не остаётся.
4. Внутренние ссылки — `Link` из `@/components/Link`; переходы в клиенте —
   `useLocaleRouter()`; серверный `redirect()`, `location.assign` и голый
   `<a href>` на страницу — через `lp(locale, …)`.
5. Метаданные: `title`, `description`, `openGraph.locale` (`ogLocale`),
   `alternates` с `languages: { ru, en, 'x-default' }` у каждой индексируемой
   страницы. Где версия одного языка бывает с noindex (патч, архив
   обновлений — в поиск их пускает пересказ своего языка), hreflang ведёт
   только на версии в поиске, как у адреса в карте сайта: `indexedHreflang`
   в `app/[lang]/game/[appid]/news/alternates.ts`. x-default — английская
   версия, если она среди перечисленных, иначе русская: гость с языком,
   которого нет среди версий, получает английский, как на «/» вне СНГ. Одно
   правило в `alternates` (`lib/i18n.ts`), `languages()` карты сайта
   (`app/sitemap.ts`) и `indexedHreflang`.
6. Чего НЕ переводить:
   - словари и эвристики, которые сравнивают русский ТЕКСТ ДАННЫХ (разбор
     русских отзывов, распознавание русского в патчноутах, `isRussianText`) —
     это логика, а не интерфейс;
   - ключи тегов (они английские и так) — переводится только подпись;
   - логи, ошибки для разработчика, комментарии в коде (комментарии в проекте
     пишутся по-русски — новые тоже);
   - названия игр, имена из Steam, текст пользователей.
7. Подпись тега — `tagLabel(tag, locale)`: для `en` это сам тег Steam.
8. Тексты модели (LLM): то, что генерируется на запрос, генерируется на языке
   запроса. То, что лежит в базе (плюсы/минусы, пересказ патча, дайджест,
   портрет), хранится по языку; нет английского — блок на `/en` не
   показывается, а не показывается по-русски.
9. Годится ли текст из данных (описание магазина, заголовок поста, тело
   патчноута) для показа на `/en`, решает `isEnglishText` из
   `lib/englishtext.ts` (реэкспорт в `lib/gamedesc.ts`), а не `textLang` и не
   `isRussianText`: `textLang` / `textLangOn` выбирают только атрибут `lang`
   (голос скринридера), а китайский или немецкий текст для них тоже «не
   русский».
10. Подпись картинки превью (`og:image:alt`, `twitter:image:alt`). Русская
    страница отдаёт ровно ту подпись, что и до перевода, — без
    «нейтральных» замен вроде голого «imbored»: русская голова страницы не
    меняется ни на байт. Английская страница получает английскую подпись
    тем же механизмом, что уже у патча и сравнения: на `/en` страница
    объявляет `openGraph.images` (и `twitter.images`) своего уровня с тем же
    адресом файловой карточки и английским `alt` — Next берёт images своего
    уровня вместо файла (`mergeStaticMetadata`), а на русском языке их нет,
    и работает файл. Корневая карточка (`app/[lang]/opengraph-image.tsx`) —
    так же: корневой layout на `en` объявляет её `/en/opengraph-image` с
    `alt` `siteTitle('en')` (`rootCardOn` в `app/[lang]/layout.tsx`), и
    английские страницы, которые её наследуют, получают английскую подпись.
    «Тот же адрес» — вместе с хвостом `?<хеш>`, который Next ставит файлу:
    по адресу картинки мессенджеры кэшируют превью, и без хвоста после
    перерисовки карточки английская ссылка осталась бы со старой. Где адрес
    нельзя взять у родителя (файл того же уровня, что и объявляющий его
    layout или страница), хвост приписывает `cardUrl` из `lib/cardhash.ts`:
    хеш там записан, сторож `lib/cardhash.test.ts` пересчитывает его по
    файлу.
    Страницы на `ownAddress` получают английскую подпись и в самом
    `ownAddress`: на `en` унаследованная корневая карточка
    переподписывается `siteTitle('en')` (адрес, размеры и тип — от
    родителя; twitter:image Next достраивает из openGraph с той же
    подписью). Страница без своего адреса и без своей карточки (/play,
    /explore) вливает в свою метадату `...(await rootCard(props, parent))`
    из `lib/site.ts`: на `en` — openGraph корня с той же карточкой и
    английской подписью, на `ru` — пусто. Личные /library и /compat на `en`
    зовут `ownAddress` (подпись вместе со своим og:url и canonical), на `ru`
    — только вкладка и описание. /rooms и /room/new на `en` переподписывают
    карточку родителя сами — в своём openGraph со своим og:url и canonical
    (`app/[lang]/rooms/layout.test.ts`). Экспорт `alt` у
    `opengraph-image.tsx` остаётся русским — он и есть русская подпись.
    Голову 404 под `/en` (`notFound()` страницы) подписывает своя метадата
    `app/[lang]/not-found.tsx`: на not-found Next ставит файлы корня ещё
    раз, последним уровнем (`errorMetadataItem`), и images корневого layout
    там нет, поэтому на `en` `generateMetadata` границы объявляет openGraph
    корня целиком — с той же карточкой и английским `alt`; на `ru` — пусто,
    работает файл. Это голова HTML сервера; ту, что браузер ставит после
    гидрации, собирает обычный проход метаданных — с `generateMetadata`
    самой страницы, — и 404 карточки игры, архива и патча на `en` объявляют
    там ту же карточку с английским `alt` сами (`missingMeta` в
    `app/[lang]/game/[appid]/page.tsx`, ветки «нет архива» и «нет поста» в
    `news/page.tsx` и `news/[gid]/page.tsx`); на `ru` — пустой объект, как
    был. У `/_not-found` (`app/global-not-found.tsx`) сегмента
    `[lang]` нет, и файл до него не доходит: там корневая карточка
    `/ru/opengraph-image` с русской подписью объявлена явно (`RU_ROOT_CARD`).

## Голос английской версии

- Дружелюбно и прямо, на «you». Короткие фразы. Не калька с русского: смысл и
  интонация важнее порядка слов.
- Sentence case в заголовках и кнопках («Find a game», не «Find A Game»).
- Без лишних восклицаний. Шутки и игра слов — переносить смыслом или
  заменять равной по силе английской, а не переводить буквально.
- Ярлыки отзывов Steam — официальные английские: Overwhelmingly Positive,
  Very Positive, Positive, Mostly Positive, Mixed, Mostly Negative, Negative,
  Very Negative, Overwhelmingly Negative.
- Длина: английская подпись не должна быть длиннее русской там, где ширина
  измерена (шапка на 768 px, нижняя панель на 360 px, кнопки голосования).
  Если не помещается — ищется короче, а не сжимается шрифт.

## Функции lib с языком

Справочник для тех, кто переводит страницы: что в `lib/` уже говорит
по-английски и как его звать. Язык страница берёт, как написано в разделе
«Как страница узнаёт язык», и передаёт в каждую функцию отсюда, где он есть.
Русский вывод без языка — прежний до байта, поэтому пропущенный `locale`
ничего не ломает, а молча оставляет на `/en` русский текст: проверять
глазами и тестом «нет кириллицы».

Общие правила:

- **Позиционный хвост** `locale: Locale = 'ru'` — у большинства функций:
  передаётся последним аргументом.
- **В опциях** `{ …, locale }` — там, где опции уже были: `discountView`,
  `discountEndsLabel`, `formatPrice`, `dateLabel`, `buildPickContext`,
  `shelfCardView`, `loadCompatInvite`, `loadCompat`, `buildTrivia`,
  `buildGroupDeck`, `heuristicPicks`, `claudePicks`, `claudePortraitText`,
  `playCacheKey` и все `*Ld` из `lib/jsonld.ts`.
- **Обязательный** язык (без значения по умолчанию): `descriptionFor`,
  `storeUrlFor`, `siteTitle`, `siteDescription`, `ogSite`, `localeAlternates`,
  `tr`, `pl`, `fmtNumber`, `fmtDate`, `lp`.
- **null на en — значит «блока нет»**, а не «подставь русское»: так отвечают
  `ruLangLine`, `languageTrait` (на en всегда), `descriptionFor`, `prosConsOn`,
  `dailyReasonBase(…, 'en')`, `getUserPortrait(…, 'en')`, `claudePortraitText`,
  `personaLabel` без ника. Это правило п. 8 из «Как переводить строку».
- **Ридеры без языка**, которые отдают английский слот рядом с русским:
  `GameMeta.shortDescriptionEn` (getGameMeta, getGamesMetaLite,
  getGamePageRow(s)), `StoredNews.tldrEn` / `titleEn` (getGameNews,
  getNewsPage, getFeedForApps, getRssFeedForApps, cachedMajorFeed),
  `NewsHead.titleEn` (getGamePatchHeads), слот `en` плюсов и минусов
  (getGamePageRow → `prosConsOn`), `DailySelection.en` (→ `dailyReasonBase`).
  Сырые поля на странице не читаются — через функции ниже.
- **Запасной вариант /en** у текстов модели и данных — спрятать блок. У поста
  издателя без английского: заголовок — `newsTitleOn(item, gameName, locale)`
  (lib/newspage): `titleEn`, иначе сам заголовок, если он `isEnglishText` или
  в нём нет букв («1.0.3»), иначе «{Game} update»; тело — только
  `isEnglishText`, иначе ссылка на оригинал в Steam; в индекс — только с
  `tldrEn`.
- **Русские константы** остаются ради старых вызывающих и тестов:
  `SOURCE_BADGE*`, `EDGE_BADGE`, `EDGE_LINE`, `NUDGE_LABEL`, `LIVE_DEFAULT`,
  `COUNTING_STAGE`, `STEPS`, `DESTINATIONS`, `LIBRARY_FILTERS`, `SHELF_EMPTY`,
  `PINNED_REASON`, `NEW_ROOM_HINT`, `REFUND_NOTE*`, `PATCH_SINCE_LEAD`,
  `OTHER_STORE_GENRE`, `HUB_GENRES[tag].title`, `FORGET_LABELS`, `SITE_TITLE`,
  `SITE_DESCRIPTION`. В коде страниц их не остаётся — только функции.

### Числа, даты, время, цены

- `freshness(publishedAt, nowSec, locale?)` — «today», «2 days ago», «a year ago».
- `dateLabel(atSec, { year?, locale? })` — «August 12», «August 12, 2026» (UTC).
- `minutesAgoLabel(minutes, locale?)`, `dayLabel(dateStr, locale?)` — «5 min ago», «August 19».
- `playedShort(minutes, locale?)` / `playedWords(minutes, locale?)` — «20 min», «1,234 h» / «25 minutes», «1 hour».
- `playedLine(minutes, locale?)` (lib/outcome) — «3 h 20 min», «2,435 h».
- `outcomeQuestion(ask, locale?)`, `eveningPlayed(e, locale?)` — целые фразы «How is it?» / «not checked yet».
- `discountView(meta, nowSec, { urgency?, calendar?, locale? })` — `endsLabel` на языке страницы («2 days left», «until Nov 24»);
  `discountEndsLabel(endsAt, nowSec, { calendar?, locale? })` — то же отдельно, на en битая дата — null.
- `formatPrice(minor, cc, { whole?, locale? })` — «$59.99», «₽1,999». Валюту решает регион `cc`, запись — язык.
- `priceWhere` / `notSold` / `notSoldShort` / `byPrices(cc, locale?)` — «price on Russian Steam», «not on Russian Steam»;
  регион называется прилагательным `STEAM_REGIONS[cc].en`, «your region» — никогда.
- `ogNum(n, locale?)` — «4,404» для карточек next/og.
- `gamesCaption` / `hoursCaption` / `unplayedCaption(n, locale?)`, `playedFact(minutes, locale?)` — подписи фактов.
- `yearEyebrow(y, locale?)` — «2026 in review», «2026 · since September 23».
- `backlogEquivalent(minor, cc, seed, locale?)` — та же шутка того же номера по-английски (шаурма → burrito).
- `refundNote(tone, locale?)` — «Steam refunds it…».
- `verdict(percent, locale?)`, `commonTimeLine(d, locale?)` (lib/compat) — вердикт и строка общего времени.

### Каталог, карточка игры, разметка

- `tagLabel(tag, locale?)` — подпись тега; на en — сам ключ Steam. `tagRu` в коде страниц не остаётся.
- `hubTitle(tag, locale?)` — заголовок страницы жанра («Roguelikes»), не понижать регистр.
- `facetCopy(facet, locale?)` (lib/gamehub) → `{ title, heading, label, basis }` подборки по факту (`/games/coop`,
  `free`, `split-screen`, `short`); английское — поле `en` у `HUB_FACETS`, `f.title` и `f.label` в коде страниц не остаются.
- `otherStoreGenre(appid, locale?)` — жанр обложки игры другого магазина.
- `sessionTrait(meta, locale?)` → `{ label, value }` («Session ~40 min»); одной фразой —
  `sessionPhrase(trait, locale)` («~20 min sessions»): вместо склейки `${label.toLowerCase()} ${value}` на /play и в колоде.
- `entryTrait`, `characterTrait(meta, locale?)`, `lengthTrait(meta, { endless }, locale?)` — строки «Ramp-up», «Feel», «Playtime».
- `ruLangLine(ru, locale?)`, `languageTrait(meta, locale?)` — на en всегда null: строки о русском там нет.
- `reviewsBrief(percent, total, locale?)` → `{ short: '92% of 48K', full }`, `reviewsLine(percent, total, locale?)` — фраза целиком;
  `steamScoreLabel(label, locale?)` — ярлык Steam (на en — как есть: «Very Positive»).
- `descriptionFor(meta, locale)` (lib/gamedesc) — описание магазина: ru — как лежит; en — `shortDescriptionEn`,
  своё английское или наложение других магазинов, иначе null. `storeUrlFor(meta, locale)` — страница магазина
  игры не из Steam на языке страницы. `isEnglishText(text)` — годится ли текст для /en.
- `nearPlayedLabel(minutes, locale?)` (lib/ownednear) — подпись своей похожей игры: «25 min played», «never launched»;
  null — время скрыто настройками Steam.
- `claimsNoUpdates(text)` (lib/modeltext) — без языка, правила обоих языков сразу (язык выбирает сам текст): минус
  «не обновляют» / «isn't updated» над свежим патчем `loadGamePage` прячет в обоих слотах.
- `loadGamePage(appid, locale?)` — плюсы/минусы, заголовки и пересказы патчей уже на языке страницы
  (`prosConsOn(stored, locale?)` — на en только слот en, иначе null; `cardNews(item, locale?, gameName?)` — на en
  `title` из `newsTitleOn` (`titleEn` → английский заголовок → «{Game} update»), `tldr` из `tldrEn`, без него поля нет).
- `gameDescription({ meta, facts, prosCons, verdict }, locale?)` — meta description; `verdict` — `deadVerdict(meta, nowSec?, locale?)`
  (язык — после часов), `prosCons` — из `loadGamePage` того же языка.
- `reviewPulse(meta, facts, nowSec, locale?)` — отзывы за 30 дней («30 days through October 8: 71% of 7,948 reviews are
  positive — …», значение — `reviewsLine`, как у кольца); строки «На русском» на en нет, как у `languageTrait`.
- `hookTrait(hook, locale?)`, `gameTraits(meta, hook, locale?)` — строки фактов карточки.
- `explainMatch(profile, meta, mood, tagWeight?, locale?)` / `moodWordsOf(meta, mood, locale?)` — настроение словами («calm, unhurried»).
- `gameJsonLd` / `gameBreadcrumbLd` / `genreBreadcrumbLd` / `genreItemListLd` / `patchArticleLd` / `patchBreadcrumbLd({ …, locale })`,
  `archiveBreadcrumbLd({ …, locale })`, `websiteJsonLd(baseUrl, locale?)` — адреса, крошки и описание на языке страницы;
  крошка архива — `archiveCrumb(locale?)` («Updates»), а `pageNameRu(meta, nameRu, locale?)` на en — null: русского
  `alternateName` и второй строки под заголовком на /en нет. `patchArticleLd` берёт `item.tldr`
  на языке страницы (на en — `tldrEn`) и сам ставит `inLanguage`; заголовок у него и у `patchBreadcrumbLd` — сам
  через `patchHeading` (`item` с `titleEn`, как его отдаёт чтение): тот же, что в h1. Автор и издатель статьи — главная
  той же версии (`/en` на английской), как `WebSite`.
- `newsTitleOn(item, gameName, locale?)` — заголовок поста на языке страницы (ru — как есть; en — `titleEn`, английский
  заголовок, заголовок без букв, иначе «{Game} update», без игры — «Update»; номер версии или сезона из заголовка
  издателя общий заголовок сохраняет — `patchToken(title, gameName?)`: «{Game} update 7.41d», «{Game} season 5 update»,
  дата через точки номером не считается). Его результат и идёт в `newsHeading`, `newsPageTitle` и строки лент; сырой
  `item.title` на /en не показывается. `patchHeading(item, gameName, locale?)` (lib/newspage) — заголовок h1, карточки,
  headline и последней крошки: общий «{Game} update» целиком, остальное — `newsHeading`; на ru — ровно `newsHeading`.
- `newsPageTitle(title, gameName, publishedAt?, locale?)` — «Portal 2: Update (Aug 3, 2026) — what changed»; `title` — уже из `newsTitleOn`,
  общий «{Game} update» — целиком, как у `patchHeading`: «Counter-Strike 2 update (Aug 12, 2026) — what changed»;
  `newsDescription(item, gameName, locale?)` — `item.tldr` передаётся на языке страницы, `item.titleEn` читается сам
  (запасной заголовок — `newsTitleOn`), начало поста на en — только `isEnglishText`;
  `newsIndexable(tldr, listed)` — тоже с пересказом своего языка; `patchShareUrl(origin, appid, gid, locale?)`.
- `RssChannel.language` (lib/rss) — `htmlLang(locale)` версии ленты; ридер /en — `getRssFeedForApps(…, 'en')`
  (у неанглийского поста без `tldrEn` тело пустое — тем же `isEnglishText`, что в `newsDescription`; заголовок записи —
  `newsTitleOn`).
- `searchStatus(phase, query, found, locale?)` — строка состояния поиска каталога.
- `textLangOn(page, text, gameName?)` — атрибут `lang` куска чужого текста: на en — 'ru' для русского, иначе undefined.
- `langOn(locale, text)` — то же для куска данных целиком (название игры, ник): 'ru' только на /en, на ru — undefined, атрибута нет.
  В серверном компоненте — разворотом `{...langAttr(locale, text)}` (lib/textlang): `lang={undefined}` атрибута в HTML не даёт, но
  RSC-часть страницы сериализует его строкой `"lang":"$undefined"` — на русском хабе у каждой капсулы.
  Фраза с названием внутри — `withForeignRuns(locale, text, [name])`; во флекс-родителе (`.link-more`) — ещё и `oneItem(…)`
  (lib/textlang): куски фразы одним флекс-элементом. Атрибуту (`aria-label`, `alt`) lang не поставить — русское название
  на /en в подпись не встаёт (`shotLabels`, подпись ролика `TrailerPreview`).
- Русские названия в `games.name` без второго — `russianNamedGames(db)` (lib/db, счёт — в `catalog:report`); английская запись
  для них сразу — `repairRussianNames(db, { dryRun? })` (lib/catalog, `npm run catalog:repair-names`). Описание магазина —
  текстом: сущности appdetails (`&amp;`, `&quot;`) расшифровывает `storeDescription` (lib/catalog) на каждой дороге в колонку.
