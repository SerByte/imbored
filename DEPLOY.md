Гайд написан под текущее состояние проекта (Next.js 16, App Router, `node:sqlite`).
Разделено на **что делаешь ты** (аккаунты, клики) и **что делаю я** (код).

## 0. База данных: миграция на Turso — ✅ сделано

Раньше база была файлом `data/imbored.db` через встроенный `node:sqlite`. На Vercel это не работает:
файловая система serverless-функций эфемерная, а запросы приходят в разные инстансы — библиотека
пользователя исчезала бы между запросами.

**Проект переведён на Turso** (облачный SQLite):

- `lib/db.ts` полностью переписан на асинхронный клиент `@libsql/client`;
- заодно убраны N+1 запросы — `getStaleAppids`, `getGamesMeta` и доска комнат теперь ходят в базу
  один раз вместо цикла;
- `getDb()` возвращает промис с кэшем на процесс: миграции схемы выполняются один раз за холодный старт;
  на уже доведённой базе это четыре обращения к Turso, потому что ALTER и пересборки закрыты версией
  схемы (`schema_v` в `catalog_meta`). Добавляешь колонку — подними `CURRENT_SCHEMA_V` в `lib/db.ts`,
  иначе живая база её не получит;
- **локально Turso не нужен** — если `TURSO_DATABASE_URL` не задан, используется файл `data/imbored.db`,
  так что дев-режим и демо работают без единого ключа.

Проверено: 101 тест зелёный, продакшен-сборка чистая, база создаётся с нуля, все сценарии
(подбор, комната с матчем, совместимость, портрет) прогнаны на живом сервере.

## 4. Vercel (делаешь ты, 10 минут)

1. [vercel.com](https://vercel.com) → **Sign up with GitHub** (дай доступ к репозиторию `imbored`).
2. **Add New → Project** → выбери `imbored` → **Import**.
3. Framework Vercel определит сам (Next.js). Build-команды **не трогай**.
4. Разверни **Environment Variables** и добавь (все — для Production, Preview и Development):

| Переменная | Значение | Обязательна |
|---|---|---|
| `TURSO_DATABASE_URL` | `libsql://...` из шага 3 | да |
| `TURSO_AUTH_TOKEN` | токен из шага 3 | да |
| `SESSION_SECRET` | длинная случайная строка (32+ символа) | **да, критично** |
| `APP_BASE_URL` | `https://imbored.cc` | да |
| `STEAM_API_KEY` | ключ из steamcommunity.com/dev/apikey | да (иначе только демо) |
| `ANTHROPIC_API_KEY` | ключ с platform.claude.com | нет (без него — эвристика) |
| `CRON_SECRET` | длинная случайная строка | **да, иначе патчноуты не обновляются** |
| `STEAM_STORE_CC` | `us` или `ru` — регион цен | нет |
| `LLM_MODEL` | переопределение модели, по умолчанию `claude-haiku-4-5` | нет |
| `NEXT_PUBLIC_DONATE_URL` | ссылка на Boosty / Ko-fi | нет |

> **Про срок входа.** Кука живёт год и продлевается при каждом заходе (роут
> `/api/session/touch`), так что переавторизовываться через Steam не нужно, пока
> заходишь хотя бы раз в год. Сессии лежат в таблице `sessions` и гасятся
> кнопками на `/library` — по одному устройству или сразу по всем. Смена
> `SESSION_SECRET` тоже разлогинивает, но всех и сразу, так что для обычного
> выхода она не нужна.

> **`SESSION_SECRET` — не пропускай.** Им подписывается кука сессии. Сейчас в коде есть
> дев-заглушка; если оставить её в проде, куку можно будет подделать и зайти под чужим SteamID.
> Сгенерировать: любой менеджер паролей, длина 32+, или попроси меня — выдам строку.

5. **Deploy**. Через ~2 минуты получишь адрес вида `imbored-xxxx.vercel.app` — уже рабочий.

### Про тариф

Hobby (бесплатный) по правилам Vercel — **для некоммерческих проектов**. Как только появятся
донаты или подписка, формально нужен **Pro ($20/мес)**. Для запуска и тестов Hobby подходит.

## 5. Домен imbored.cc (делаешь ты, 10 минут + ожидание DNS)

1. В Vercel: проект → **Settings → Domains** → введи `imbored.cc` → **Add**.
2. Vercel покажет, какие записи создать. Обычно:
   - `A` запись, имя `@`, значение `76.76.21.21`
   - `CNAME`, имя `www`, значение `cname.vercel-dns.com`
3. В Cloudflare: домен `imbored.cc` → **DNS → Records** → добавь эти записи.
   **Важно: облачко должно быть серым (DNS only), не оранжевым** — иначе Cloudflare встрянет
   между пользователем и Vercel, и сертификат будет выпускаться с ошибками.
4. Подожди 5–30 минут. Vercel сам выпустит HTTPS-сертификат и покажет зелёную галочку.

## 6. Steam: боевой домен и приватность (делаешь ты, 5 минут)

1. Ключ на [steamcommunity.com/dev/apikey](https://steamcommunity.com/dev/apikey) сейчас

3. Проверь, что вход через Steam возвращает на боевой домен: это делает `APP_BASE_URL`

   или на адресе `*.vercel.app`, сперва перекидывает на `APP_BASE_URL` и заканчивается там
   же — так и задумано: кука входа живёт на том домене, куда вернёт Steam.

## 6.5. Каталог игр: наполнение (делаешь ты, один раз)

Приложение работает и без этого шага, но блок «Нет в твоей библиотеке» будет
пустым: рекомендовать новое не из чего, пока каталог не наполнен.

Каталог собирается **локально**, а не в облаке. Так задумано: отладка прямо по
Turso сожгла бы квоту записей, а локальный SQLite пишет мгновенно.

```bash
npm run seed:catalog
```

Обходит магазин Steam и складывает карту территории — около 170 тысяч игр
с тегами, датами выхода, отзывами и ценами. Занимает 15–40 минут. Прогон
**возобновляемый**: если прервётся, тот же запуск продолжит с места обрыва.
Начать заново — `npm run seed:catalog -- --restart`.

```bash
npm run catalog:promote -- --limit=3000
```

Отбирает самые обсуждаемые игры, догружает теги с весами и арт, спрашивает
свежие отзывы у совместных игр и раскладывает по рабочим таблицам, применяя
фильтры актуальности. Можно запускать повторно — очередь двигается дальше.

```bash
npm run catalog:report -- --name=counter
```

Показывает, **какие решения принял фильтр**: сколько игр отсеяно и почему,
какие версии признаны устаревшими. Вытеснение версий стоит просматривать
глазами — ошибка здесь заметнее пользователю, чем лишняя игра в выдаче.

```bash
npm run news:sync -- --limit=200
```

Собирает патчноуты: обходит RSS-ленты игр, отделяет обновления от анонсов и
распродаж, просит Claude пересказать крупные в одну-две фразы. Наполняет
вкладку «Что нового» и блок патчей на странице игры.

Дальше это делает крон сам (`vercel.json` → `/api/cron/news`), но **первый
массовый обход дешевле прогнать здесь**: у функции на Vercel потолок 60 секунд
на вызов, а тут ограничений нет. Темп — 1.7 секунды на игру, тот же лимитер
хоста, что у отзывов, так что 200 игр это примерно 6 минут.

Прогон возобновляемый: очередь и её курсоры живут в таблице `news_poll`,
повторный запуск продолжает с места обрыва. Посмотреть, кого опросит, не
трогая сеть — `npm run news:sync -- --dry-run`.

**Заливка в облако.** Скрипты пишут в Turso, если задана переменная окружения:

```bash
TURSO_DATABASE_URL=... TURSO_AUTH_TOKEN=... npm run catalog:promote -- --limit=3000
```

Порядок: сначала собери и проверь каталог локально, потом залей в облако.
Наоборот — дорого и медленно.

**Патчноуты после деплоя.** Крон закрыт секретом, поэтому `CRON_SECRET` должен
быть в переменных Vercel — без него роут отдаёт 401 и лента перестаёт
пополняться. На тарифе Hobby Vercel зовёт крон примерно раз в сутки независимо
от расписания в `vercel.json`, поэтому пропускная способность набирается
цепочкой вызовов: срез отвечает сразу, работает в фоне и сам зовёт следующее
звено. На Pro можно сгустить расписание до `0 */3 * * *` и поднять
`maxDuration` до 300 — код при этом не меняется.

Проверить руками:

```bash
curl -H "x-cron-secret: $CRON_SECRET" https://imbored.cc/api/cron/news
```

**Живы ли кроны.** Код ответа выше — это 202 до всякой работы, упавший срез
по нему не виден. Каждое звено пишет отметку о себе в `catalog_meta`
(`news_last_slice`, `digest_last_slice`, `pages_last_slice`), и её читает
`/api/cron/health`: 200 — все живы, 503 — какой-то крон молчит дольше порога
(новости и пересказы — 3 часа, карточки — 26), упал или оборвал цепочку; в
ответе видно, какой и почему. Крон на паузе (`*_paused = 1`) проверку не
валит, но помечен `paused`. Этот же адрес дёргает часовой воркфлоу
`.github/workflows/cron.yml`, так что поломка приходит письмом от GitHub.

```bash
curl -H "x-cron-secret: $CRON_SECRET" https://imbored.cc/api/cron/health
```

У карточек расписание одно, суточное, поэтому их подстраховывает крон
новостей: закончив свою цепочку, он пинает `/api/cron/pages`, если отметка
карточек старше 26 часов или последняя запись — обрыв передачи звена.
Отказ передачи звена или пинка пишется в Runtime Logs одной строкой JSON с
`"event":"cron-chain-break"`.

## 6.6. Удаление данных по запросу (делаешь ты, по письму)

/privacy, раздел 06, обещает удалить всё по письму на hello@imbored.cc за 30
дней. Удаление — одна команда, учётки Turso берутся из `.env.turso`:

```bash
npm run user:forget -- https://steamcommunity.com/profiles/7656119XXXXXXXXXX
```

Без `--apply` скрипт только считает строки по таблицам и ничего не трогает.
Если счёт похож на правду — та же команда с `--apply`: всё удаляется одной
пачкой (профиль и портрет, снимки и годовые отметки библиотеки, оценки и
баны, сессии, игра дня, голоса и участие в комнатах, комнаты этого человека
целиком, его ключи лимитера). Ссылка вида `/id/<имя>` разворачивается через
Steam API и требует `STEAM_API_KEY` в окружении; без него попроси SteamID64.

Запускать из задеплоенного кода: скрипт намеренно не гоняет миграции, и если
в базе ещё нет таблицы из списка, пачка откатится целиком, ничего не удалив.
Картинки портрета в кэше Vercel доживают до часа, превью в мессенджерах
отозвать нельзя — это сказано в /privacy, раздел 05.

## 7. Проверка после деплоя (делаем вместе)

По порядку на живом `https://imbored.cc`:

- [ ] Главная открывается, коллаж артов едет
- [ ] «Попробовать демо без Steam» → квиз → выдача с hero-артом
- [ ] Вход по ссылке на **твой реальный** Steam-профиль → библиотека подтянулась
- [ ] «Игра дня» показывает игру, при перезагрузке — **ту же**
- [ ] Пати: создать комнату → открыть ссылку **с телефона** → проголосовать → матч
- [ ] Совместимость: `/compat/<твой steamid>` открыть с другого устройства
- [ ] Портрет: `/portrait` — архетипы и текст
- [ ] Переключатель темы работает и запоминается
- [ ] Приватный Steam-профиль → показывается инструкция, а не пустая страница
- [ ] После наполнения каталога: в подборе есть секция «Нет в твоей библиотеке»
- [ ] В пятничном режиме «с друзьями» предлагается CS2, а не CS 1.6
